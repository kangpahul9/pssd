Problem: Barbecue

First Idea:
Keep track of two things for each family member:
- votesFor[i] = how many times member i was voted against
- votesBy[i] = how many times member i voted
This way, one loop over voter[] and excluded[] can fill both arrays.

Why it might work:
The rules say:
1. Person with the most votes against is excluded.
2. If tied, the one who voted the most is excluded.
3. If still tied, the smallest index is excluded.
With votesFor and votesBy, all tie-breaking conditions can be checked.

Try #1(Store & Loop with simple nested if statements):
Get no. of votes by each voter and no. of votes against each voter
for (int i = 0; i < voter.size(); i++)
        {
            votesBy[voter[i]]++;
            votesFor[excluded[i]]++;
        }

Compare using nested if statements and check for each value by looping over n 
for (int i = 0; i < n; i++)
        {
            if (votesFor[i] > maxValue)
            {
                maxValue = votesFor[i];
                maxIndex = i;
            }
            else if (votesFor[i] == maxValue)
            {
                if (votesBy[i] > votesBy[maxIndex])
                {
                    maxValue = votesFor[i];
                    maxIndex = i;
                }
                else if (votesBy[i] == votesBy[maxIndex])
                {
                    if (i < maxIndex)
                    {
                        maxValue = votesFor[i];
                        maxIndex = i;
                    }
                    else
                    {
                        continue;
                    }
                }
                else
                {
                    continue;
                }
            }
        }
Then return maxIndex

Silly mistake forgot a semicolon


Problem: RunLengthEncoding

First Idea:
Scan the string left to right. If a digit is found, accumulate it into currNumber. 
When a letter is found, pair it with either:
- currNumber (if digits were seen before it)
- 1 (if no digits were seen, i.e., currNumber == 0)
Store letters and numbers in vectors, then expand them at the end.

Why it might work:
Run-length encoding always follows the pattern: [number][letter].
Numbers can be omitted (default = 1). Using a running currNumber lets us handle multi-digit numbers like 21Z or 123A. 
Expansion is straightforward: append the letter numbers[i] times to result. 
Add a running sum to check if decoded length > 50 and return "TOO LONG" early.

- If digit: currNumber = currNumber * 10 + (c - '0')

Problem: RGBStreet

First Idea:
Use dynamic programming. Define dp[i][c] as the minimal cost to paint up to house i, with house i painted color c.
At each step, the current color’s cost is added to the minimum cost of painting the previous house with a different color.

Why it might work:
DP has optimal substructure: the minimal cost of painting house i with color c only depends on the best results of house i-1 with the other two colors.
This enforces the “no two adjacent houses same color” condition without explicit if-checks.

Try #1 (Initial Loop):
Parsed the costs but mistakenly tried to use dp[i-1] directly from i=0.
This caused out-of-bounds access because dp[-1][...] is invalid.

Try #2 (Fixed with Base Case):
Set base case dp[0][0..2] = cost[0][0..2].
For i ≥ 1:
    dp[i][0] = cost[i][0] + min(dp[i-1][1], dp[i-1][2])
    dp[i][1] = cost[i][1] + min(dp[i-1][0], dp[i-1][2])
    dp[i][2] = cost[i][2] + min(dp[i-1][0], dp[i-1][1])
Answer = min(dp[n-1][0], dp[n-1][1], dp[n-1][2])

Reflection:
The DP formulation eliminated the need for checking conditions like dp[i][j] != dp[i-1][j].
The base case was the key missing piece. 
After fixing that, the solution matched all sample outputs and is efficient for n ≤ 20.

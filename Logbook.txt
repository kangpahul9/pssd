Instead of performing literal insertions, we can view it as “sliding” the shorter string across the longer one to find the alignment that yields the fewest mismatched characters.

Trying all valid offsets (from aligning the start to aligning the end) guarantees we’ll find the minimal difference. Sorting or backtracking isn’t needed, only pairwise comparisons for each possible alignment should be enough.

Problem: BlockEnemy

First Idea:
The core realization is that every edge cut in a tree cleanly separates it into two parts so if one side of an edge contains occupied towns and the other side also contains occupied towns, that edge must be destroyed.

Why it might work:
By performing a depth-first traversal, we can compute how many occupied towns lie in each subtree. If both sides of an edge contain at least one occupied town, we mark that edge for destruction and add its cost.

Try #1 (Tree Construction + DFS Propagation):

Reflection:
The beauty lies in how a seemingly global optimization (“disconnect all occupied towns”) reduces to a local check during recursion. Each edge independently decides whether it needs to be destroyed, based on simple subtree counts. The structure of the tree ensures there are no cycles or redundant decisions.

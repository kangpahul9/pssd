Problem: FairWorkload

First Idea:
We need to split filing cabinets (each with a number of folders) into contiguous groups for workers.
Goal: minimize the maximum workload any worker gets.
Classic “minimize the maximum” → use binary search on the answer.
For each candidate workload mid, check feasibility with a greedy pass.

Why it might work:
The maximum possible workload is the sum of all cabinets (one worker does all).
The minimum possible workload is the largest single cabinet.

Try #1 (Binary Search with Partition Check):
while (st<=sum)
        {
            mid = st + (sum-st)/2;
            if (partition(mid,folders,workers))
            {
                if (mid<result)
                {
                    result = mid;
                    sum=mid-1;
                }    
            }
            else{
                st=mid+1;
            }
        }
        return result;
        
Reflection:
Initially, I set lower bound = 0, but that allowed impossible workloads smaller than the max element. Fixed to st = max(folders).
Also fixed infinite loop bug: when infeasible, move st = mid + 1, not st = mid.
Binary search now cleanly narrows to the minimal feasible workload.


Problem: VeryInterestingMovie

First Idea:
We need to seat as many students as possible in a theatre.
Constraint: no two students in the same row can sit in adjacent seats.
Rows are independent, so solve each row separately and add up the results.
Strategy: scan left to right in each row; whenever a seat is available (Y), place a student and skip the next seat.


Why it might work:
If a seat is available and we don’t place a student, it cannot help to leave it empty unless it allows a later placement.
But by taking the first available seat, we guarantee that the skipped seat can’t be used anyway (due to adjacency).

Try #1 (Greedy Scan):
int maximumPupils(vector<string> seats) {
    int result = 0;
    for (string row : seats) {
        for (int i = 0; i < row.size(); i++) {
            if (row[i] == 'Y') {
                result++;
                i++; 
            }
        }
    }
    return result;
}

Reflection:
The greedy logic works because adjacency is local: once we choose seat i, seat i+1 is unusable anyway, so skipping it is correct.


Problem: MinimalDifference

First Idea:
We need to find a number X between A and B whose digit sum is closest to the digit sum of C.
If multiple numbers tie, choose the smallest such X.

Why it might work:
Keep track of the current “best” number using the absolute difference from digitSum(C).
Checking all numbers in [A, B] is at most 100,001 iterations, well within time limits.

Try #1 (Brute Force with Digit Sum):
for (int i = A; i <=B; i++)
    {
        sumNum = digitSum(i);
        int diff = abs(sumNum - sumC);
        if (diff < bestDiff) {
                bestDiff = diff;
                bestNum = i;
            } else if (diff == bestDiff && i < bestNum) {
                // tie-breaker: smaller number
                bestNum = i;
            }
        }
        return bestNum;

Reflection:
Brute force all numbers in [A, B], compute digit sums, track the closest to digitSum(C), and break ties by smaller value.
